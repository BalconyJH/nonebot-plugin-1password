# Catalog

A Catalog is an administrator-maintained resource allowlist, not a browser for a 1Password account. Queries must satisfy Catalog visibility. Requests and executions must additionally match an exact Action Policy.

## Public and private snapshots

Remote Broker mode uses two separate documents:

- The NoneBot public Catalog contains alias, title, description, owner, classification, discoverable, and allowed_groups fields; its schema rejects `secret_references`.
- The Broker private Catalog contains the same safe metadata plus mappings from Provider-declared names to `op://` References.

Aliases and Policy coordinates must match on both sides, but the public file must not be generated by copying the private file. `PublicCatalogLoader` fails closed when it encounters extra reference fields.

Local mode loads only the private Catalog because the Backend and Provider reside inside the NoneBot process.

## Visibility

A resource with `discoverable = false` cannot be searched or viewed. An empty `allowed_groups` adds no restriction; when non-empty, the principal must match at least one explicit group. Platform roles from Uninfo do not automatically become groups. Groups come only from non-default `group:<name>` roles on the Permission user.

Unknown and invisible aliases produce the same result. Visibility does not imply request eligibility: the Action Policy also checks requester groups, all requester permissions, the scene, and the UTC time window.

## Secret Reference

A Reference in the private Catalog must be a three- or four-segment `op://` path, and each key must correspond exactly to a name in the Provider's `ActionDefinition.secret_names`. Binding construction selects only keys declared by the Provider, so extra fields are never passed to it. Missing fields, an unknown Provider, or an unmatched resource make the entire execution boundary unavailable.

A Catalog must not store Secret values, tokens, OTPs, private keys, share URLs, HTTP headers, arbitrary URLs, or command templates.

## Loading semantics

The current lifecycle loads one immutable snapshot at startup and provides no in-conversation reload command. It fails closed for a missing document, unknown fields, duplicate aliases, an incorrect version, or an invalid Reference. After changing a document, run tests offline before performing a rolling restart appropriate to the deployment platform.

See [Catalog Schema](../reference/catalog-schema.md) for the complete format.
